# Purpose

The Provenance Model establishes the governance framework for documenting the origin, ownership, processing history, transformations, validation, and lifecycle of every resource managed within the Global One Health Intelligence Framework (GOHIF).

Complete provenance ensures scientific transparency, reproducibility, accountability, and long-term stewardship.

---

# Objectives

The Provenance Model aims to:

- Record the complete history of every resource.
- Preserve links to original scientific sources.
- Track all transformations and processing activities.
- Document responsible contributors.
- Support auditability and reproducibility.
- Enable FAIR-compliant provenance.
- Facilitate future computational provenance tracking.

# Provenance Components

Every provenance record should include:

## Resource Identity

- GOHIF Resource ID
- Resource Name
- Resource Type
- Domain
- Version

---

## Origin

Record:

- Original source
- Source institution
- Repository
- Dataset accession
- DOI or persistent identifier
- Citation

---

## Acquisition

Record:

- Acquisition method
- Acquisition date
- Responsible contributor
- Import workflow
- Source version

---

## Processing History

Each transformation should record:

- Processing step
- Processing date
- Responsible contributor
- Workflow identifier
- Software used
- Parameters
- Output generated

---

## Validation History

Record:

- Validation status
- Reviewer
- Validation date
- Benchmark status
- Quality assessment
- Approval decision

---

## Version History

Every revision should record:

- Version number
- Release date
- Previous version
- Summary of changes
- Approval authority

---

## Access History

Where applicable record:

- Access level
- Distribution method
- License
- Usage restrictions

# Alignment with W3C PROV

The GOHIF Provenance Model is conceptually aligned with the W3C PROV framework.

Core concepts include:

## Entity

A dataset, document, model, workflow, figure, table, or computational artifact.

## Activity

Any acquisition, transformation, validation, synchronization, or computational process.

## Agent

A person, organization, software component, or governance process responsible for an activity.
